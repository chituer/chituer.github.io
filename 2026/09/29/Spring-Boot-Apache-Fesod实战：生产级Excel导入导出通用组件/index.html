Spring Boot + Apache Fesod 实战：打造生产级 Excel 导入导出通用组件（异步任务 + 错误报告 + 模板填充一条龙）

上一篇《Apache Fesod 入门教程：高性能 Excel 处理从 0 到 1》讲清了 Fesod 的核心 API 和独立使用方式。但真到了 Spring Boot 项目里落地，你会发现事情远不止”读和写”那么简单——

  • 大文件上传超时、接口响应太慢？→ 得搞异步任务 + 进度查询；
  • 导入 10 万行，其中 300 行有问题，怎么让用户知道哪几行错了、错在哪？→ 得生成错误报告 Excel 供下载；
  • 导出合同、报价单、财务报表这类格式复杂的文件，用纯代码拼样式写死？→ 得用模板填充（Fill API），运营同学自己改模板就行；
  • 每个业务模块都复制一遍读写代码？→ 得封装通用 ExcelService，业务只关心”写你的 VO 类 + 你的业务逻辑”。

这篇就把这些生产环境的硬需求一次性解决，直接打造一个可复用、可落地、可扩展的 Spring Boot + Fesod 通用组件。所有代码复制即可运行。

7）生产环境避坑 & 调优清单 ⚠️

坑点现象解决方案
异步任务不生效@Async 方法和调用方在同一个类里异步方法必须放到另一个 Bean中（Spring AOP 代理原因）。本文 ExcelTaskService 被 Controller 调，天然跨 Bean，OK
任务状态丢失Redis 挂了或重启关键任务改为 DB + Redis 双写；非关键任务 Redis 24h 过期足够
大文件上传超时Nginx / 网关 504Nginx 调 proxy_read_timeout + 前端用分片上传
百万行导出 OOMdoWrite(list) 全查内存永远用供给式 writeBigData，分页查 DB 边查边写
导入时行号不准报错指向的行跟 Excel 对不上context.readRowHolder().getRowIndex() + 1 才是 Excel 行号（1 基）；多 Sheet 注意切换
日期/数字格式化不生效@DateTimeFormat 写在 String 字段上日期字段必须是 java.util.Date/LocalDateTime，数字字段必须是 Number/BigDecimal
Excel 中带公式读出来是公式字符串不是值用 CellData<T> 类型接收或在 POJO 上加 @ExcelProperty 配合公式处理
文件名中文乱码下载后文件名乱码必须用 filename*=UTF-8''xxx（RFC 5987），不要只写 filename=xxx

9.2 后续可扩展方向（进阶）

  1. 多租户 + 权限：下载接口校验当前用户是否是任务提交者；
  2. 任务补偿：定时扫 FAILED 状态任务，自动重试 3 次；
  3. WebHook / 消息通知：任务完成后用 WebSocket / 钉钉 / 邮件推送，不必前端轮询；
  4. 导入模板下发：导出空模板带下拉选项（字典值）、带批注提示怎么填；
  5. 百万级数据分片导出：分多个 sheet，或分多个 zip 文件打包下载；
  6. 加解密：敏感数据导出自动加密，导入自动解密。
