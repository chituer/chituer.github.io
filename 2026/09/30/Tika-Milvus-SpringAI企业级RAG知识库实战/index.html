Tika + Milvus + Spring AI 搭建企业级 RAG 知识库（解析→切块→向量化→检索→问答一条龙可落地）

前三篇我们把「Excel 精细化处理」「全格式文档解析」逐个解决了：

  • Apache Fesod 入门：Excel 业务级读写 + 错误报告；
  • Spring Boot + Fesod 生产组件：异步任务 + 进度 + 模板填充；
  • Apache Tika 入门到生产：1000+ 格式统一文本/元数据提取 + OCR。

今天，我们把这几个工具 Spring AI + Milvus + Tika 三剑客串起来，搭一套真正可在企业落地的 RAG（Retrieval-Augmented Generation，检索增强生成）知识库。之后，你公司里 PDF、Word、Excel、PPT、Markdown、扫描件 OCR…… 上传后往知识库一丢，员工就可以用自然语言提问，拿到**”基于公司内部文档 + 带引用 + 不幻觉”** 的精准回答。

和网上玩具级 Demo 不一样，本篇会直面生产环境的 7 大硬问题：

  1. ✅ 1000+ 种格式文档解析（Tika 自带）；
  2. ✅ 智能切块（TokenTextSplitter + 按语义边界，不切断半句话）；
  3. ✅ 向量数据库选型与索引（Milvus 2.6.x，HNSW + COSINE）；
  4. ✅ Spring AI 统一 ChatClient + Embedding 抽象（换模型不改代码）；
  5. ✅ 多租户/按权限过滤（SQL-like metadata filter）；
  6. ✅ 回答自带来源引用（员工能点回去看原文）；
  7. ✅ 异步文档入库 + 进度可查（大文件不阻塞接口）。

全部代码复制即可跑通，结尾附带一张”RAG 效果调优路线图”，帮你从 60 分做到 90 分。

6.4 回答的引用不准 → 加 Rerank 重排序

相似度检索 Top-K=30 → Rerank 模型（bge-reranker、通义 Rerank）精排到 Top 6，再给 LLM。这一步通常能提升 15%~30% 准确率。

6.5 接口慢 / 成本高 → Embedding 缓存

同一个 chunk 的文本不会变，Embedding 结果可以本地 Caffeine 10 分钟缓存或 Redis 缓存，避免反复调 API：

6.6 知识库回答”胡说八道” → 加 Self-Check

让模型在回答结尾输出 [[confidence:0.9]]，低于 0.6 的直接打回”未找到”。或者让 LLM 自己二次检查：

6.7 超大文档（> 1000 页 PDF）

  • 分层分块：Parent Document Retrieval —— 检索用小 chunk (200 token)，拼 Prompt 用整个父 section (2000 token)；
  • 摘要索引：先让 LLM 给每个 section 写 1 句摘要，检索时先匹配摘要，再展开原 section。
