国内外主流AI大模型介绍

这两年大模型的迭代速度已经快到“隔周换代”。如果你在做技术选型（写作/编码/Agent/多模态/成本），最实用的方式不是背参数，而是先搞清楚：

  • 每家大模型“隶属哪个公司/生态”（决定数据合规、部署形态、产品路线）
  • 截至今天的“最新可用版本”（决定能力上限与调用方式）
  • 模型之间的“能力差异”（决定你用谁、怎么用）

本文会用一张表把国内外主流模型捋顺，并给出一个偏工程视角的能力比较与选型建议。文中图标采用 Lobe Icons 的静态资源（彩色优先用 PNG 的 *-color 变体，Hexo 可直接渲染）。

非官方（但非常常用）

这些工具不是“某家模型的官方客户端”，但在工程实践中很常见，适合把多家模型统一到一个工作流里（都需要你自己配置 API Key）：

  • aider（非官方）：终端里的“结对编程/改代码”工具，多模型可选
    • https://aider.chat/
  • llm（非官方）：一个很轻量的通用 CLI，可以把不同 provider/模型统一起来
    • https://llm.datasette.io/
  • Ollama（非官方）：本地跑开源模型（离线/隐私/低成本），适合 Qwen/DeepSeek/GLM 的开源权重
    • https://ollama.com/

提示：API Key 建议只放在环境变量或本机的密钥管理里，不要写进文章源码或仓库。

能力比较：怎么选更“工程化”

大多数场景不需要“最强模型”，而需要“最适合的组合”。可以按下面维度快速判断：

1) 推理与复杂规划（Reasoning / Planning）

  • 你需要长链路任务（多步分析、做决策、写方案、拆任务）：优先考虑带“Thinking/推理/深度思考”分支的旗舰模型。
  • 如果任务本质是“要做对”，而不是“要写得快”：优先旗舰推理档；如果主要是“写得快、便宜”：选 Flash/Lite/mini。

2) 编码与 Agentic Coding（真实工程）

如果你在做“读仓库 → 改代码 → 跑测试 → 修 bug → 继续迭代”的闭环，核心不是生成代码片段，而是：

  • 是否能稳定调用工具/读日志/持续迭代
  • 是否能处理大上下文（代码库、日志、文档）
  • 是否“跑偏”少（越做越对，而不是越做越乱）

此类任务通常 Claude / OpenAI / Gemini 的旗舰档更稳；国内侧，GLM、Qwen、DeepSeek、豆包也都有强势方向（尤其是 coding/agent 相关 SKU）。

3) 多模态（图片/文档/音视频）

  • “看图问答 / 看设计稿写前端 / PDF 抽取”：优先选多模态链路成熟的模型与平台。
  • 多模态不止是“能看图”，更重要是：输出结构化结果、可控、能跟工具结合。

4) 中文能力与本地化生态

如果你的主要输入/输出是中文（写作、运营、知识库、办公自动化），国内模型在体验、合规、接入成本上通常更顺滑；海外模型在通用性、生态与工具成熟度上仍有优势。

推荐的“组合打法”（比单押一个更稳）

下面是更贴近工程实践的组合方式：

  • 日常写作/问答（便宜+快）：Flash/Lite/mini 档
  • 关键输出（要写对/要推理）：旗舰 Thinking 档兜底
  • 编码/Agent：优先选择对工具调用/长上下文更稳定的模型；必要时用“两层路由”：
    • 低成本模型跑大规模草稿/批处理
    • 高能力模型做最终审阅/修正/关键 patch
